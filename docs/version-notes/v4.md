# Origins Original v4 — automatic Anarky timer transition

Fixes the v3 requirement to retoggle for each bomb. Leave **Freeze Anarky Bomb Countdowns (auto-follow next bomb)** enabled between races. The script waits when no eligible timer is running, restores its bit on the finished timer, and binds the next active eligible timer automatically. Initial selection and re-selection fail closed when more than one eligible timer is active. Eligibility remains restricted to the observed mission package and 230/160/180-second countdowns, excluding challenge and count-up timers.

Live diagnosis: the first timer (230 seconds) had stopped with flags 0. The second timer (160 seconds) was running with flags 2, so it was not paused. v3's single bound object never followed that second timer without reactivation. This explains the code-level transition failure; it does not establish whether the user had retoggled or whether another runtime fault was present.

A bounded helper temporarily holds the current second countdown at 97 seconds for at most three minutes while the new CT is delivered. It edits only the two countdown values, not mission/code/pause flags. Load v4 for ongoing table control. Disable the previous initializer first.

v3 first-bomb success is user-reported, but the temporary helper overlapped that test; native pause alone remains to be verified in gameplay. Internal v4 tests use actual Lua against live reads with simulated writes, including transition to the third timer, waiting before a race, ambiguity handling, restore/disable and exclusion/scope checks. No native pause bit was written by the automated test.

All other v2/v3 options and hotkeys are retained. Table files v1–v3 remain preserved. Current builder/runtime target v4. Test source: work/test_origins_anarky.py.
